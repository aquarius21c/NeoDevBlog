08리뷰와 게이트 규칙

1

셀프 체크. 담당 리드가 티켓의 완료 기준을 하나씩 확인하고 측정값·스크린샷을 핸드오프에 남깁니다.

2

크로스 리뷰. 티켓의 reviewers(예: FX는 AD와 TD)가 품질과 기술을 각각 봅니다. 반려는 사유와 수정 티켓을 남깁니다.

3

QA 검증. QA가 스모크 테스트·에셋 검증·성능 비교를 돌리고 버그를 A(진행 불가)·B(눈에 띔)·C(사소함)로 등급을 매깁니다.

4

PD 판정과 HG 승인. 스프린트 안 티켓은 PD가 닫습니다. 단계 게이트는 PD가 gate-review로 리포트를 만들고 HG가 결정 카드로 승인하거나 재작업을 고릅니다.

5

공정별 순서 테스트 (2026-10-27 HG). 테스트는 공정·에셋 단위로 나눠 한 번에 하나씩, 정해진 순서대로 합니다. 맵·충돌 → 주인공·카메라 → 발사 → 표적 → 반동·애님 → 탄착 FX → 총구 FX → 외부 팩 FX → 사운드 → HUD → 통합·성능. 단계마다 시간 제한과 통과 기준을 미리 정하고, 통과해야 다음 단계로 갑니다. 통과하면 그 에셋 파일만 커밋하고 바로 보고합니다. 시도마다 동영상을 남기고, 이름은 프로젝트_진행단계_테스트명_버전_시도횟수(예: urbanstrike_st03_weaponfire_v001_t02.mp4)로 저장합니다. 여러 에셋을 한 번에 묶어 테스트하지 않습니다. 순서표는 HG 승인 후 시작합니다. 소리·성능·통합 영상·쇼케이스 녹화는 PC 비는 시간(매일 밤 01:00~08:00 KST, HG 2026-10-27 승인)에만 돌립니다. 시작 전에 알리고 끝나면 결과를 보고합니다.

09CEO 보고 규칙과 작업 모듈화

중요 단계마다 CEO에게 보고한 뒤 진행합니다. 보고는 PD가 프로젝트 채팅으로 보내고, 같은 내용이 Studio/log와 Obsidian에 남습니다.

보고시점내용
계획 보고실행 전단계·모듈을 시작하기 전에 조사한 레퍼런스, 목표, 모듈 목록, 예상 시간, 필요한 설치·다운로드, 위험을 보고하고 바로 진행. 게이트와 CEO 결정 항목만 승인을 기다림.
완료 보고실행 후결과물 위치, 완료 기준 통과 여부, 측정값·스크린샷, 남은 문제, 다음 모듈.
지연 보고10분 초과한 모듈이 예상보다 10분 넘게 걸리면 즉시: 어디서 막혔는지, 시도한 것, 다음 시도, 새 예상 시간.
즉시 알림완료·승인·답변 필요 시 바로작업이 끝났거나, 중간에 CEO 승인이 필요하거나, CEO 답변이 필요하면 기다리지 말고 그 즉시 CEO에게 보여줌: 승인·질문은 선택 카드로, CEO가 직접 할 일은 실행할 명령이나 링크를 함께. 다음 정기 보고까지 미루지 않음. 답을 기다리는 동안 추천안으로 되돌릴 수 있는 작업은 계속.
알림 줄이기항상알림은 단계 통과·실패, HG 결정·답변 필요, 완료에만. 재시도·중간 진행은 체크리스트·웹 콘솔·Studio/log에, 반복 보고는 한 줄. 선택 카드는 프로젝트 채팅에도 같이 올려 10분 시계를 시작 (2026-10-27).
10분 자동 선택선택지를 올릴 때가장 추천하는 방법을 1번에 둔다. 10분 동안 HG 답이 없으면 1번으로 자동 진행하고 '자동 선택'이라고 보고. 예외(기다림): 유료 결제, 가입·로그인, UAC, 되돌릴 수 없는 삭제, 게이트 승인, 외부 공개 (2026-10-27 HG).
반복 보고같은 테스트·단계를 다시 할 때 바로같은 테스트나 단계를 다시 돌리거나 재시도하게 되면, 돌리기 전에 즉시 CEO에게 보고: 몇 번째인지, 왜 다시 하는지(이전 결과·실패 원인), 이번에 무엇을 바꿨는지, 언제까지 끝낼지. 같은 실패 2회면 crash-triage 규칙으로 중지 (2026-10-27 HG).
단계 보고중요 단계마다단계(S0~S6) 진입·종료, 게이트 리포트, 스프린트 시작·회고는 반드시 CEO에게 보고 후 진행.

작업 모듈화

  • 새 단계·티켓을 시작하기 전에 레퍼런스부터 조사: 공식 문서, 강연·튜토리얼 영상, 비슷한 게임 사례, 참고 에셋을 찾아 Studio/refs/<티켓>.md에 요약하고 계획 보고에 첨부
  • 모듈 1개 = 한 리드가 한 번에 끝내는 가장 작은 작업 (목표 30분 이내, 산출물 1개)
  • 티켓은 모듈 여러 개로 쪼갬: T-0004-M01, M02 … 각 모듈에 시작·종료 시각과 완료 기준
  • 모듈마다 Studio/log/YYMMDD_<티켓>-M##.md 에 한 장 기록 (한 일, 결과, 걸린 시간)
  • 모듈이 끝나야 다음 모듈 시작. 실패한 모듈은 되돌리고 원인과 함께 새 모듈로 다시

설치·다운로드는 리드 자율

  • 중간 작업 권한 위임 (2026-10-26 HG): 작업 중 필요한 중간 단계(런처·툴 조작, 설치, 다운로드, 설정, 스크립트 실행, 에디터 재시작 등)는 CEO에게 묻지 않고 리드가 직접 처리하고 결과만 보고. 예외는 게이트 승인, 유료 결제, 계정 가입·로그인, 라이선스 동의, UAC처럼 HG 손이 꼭 필요한 것
  • 무료 프로그램·플러그인·무료 에셋의 설치와 다운로드는 담당 리드가 자율 진행
  • 다운로드는 _Downloads 에 저장, 압축 해제까지 리드가 처리
  • 설치할 때마다 Studio/installs.md 대장에 이름·버전·출처·라이선스·용도 기록
  • 계획 보고에 설치 항목을 미리 적고, 완료 보고에 결과를 적음
  • 유료 결제, 계정 가입·로그인, 라이선스 동의는 CEO 결정. UAC·Epic Launcher 클릭은 PC 앞에서만 가능하니 미리 알림

멈춤. 같은 크래시·에러가 2번 나면 그대로 재시도하지 않는다. 현재 모듈을 멈추고 잠금(editor.lock)을 푼다.

2

3

4

메모리 확인. 반복 실행하며 메모리 추이 기록: stat memory, memreport -full, -llm. 의심되면 -stompmalloc(해제 후 사용 탐지), -d3ddebug, -onethread로 재현.

5

최소 재현. 모듈을 더 쪼개고 이분 탐색으로 원인 노드·에셋·스크립트 줄을 좁힌다. 같은 조건으로 3번 재현되면 확정.

6

기록. Studio/bugs/crash/C-####.md: 증상, 횟수, 로그 경로, 콜스택 상위 5줄, 가설, 시도한 것, 우회책, 리스크, 근본 해결 계획.

7

우회와 근본 해결 분리. 우회(예: 헤드리스 대신 에디터 GUI에서 실행, 기능 끄기)는 workaround로 표시하고 근본 해결 티켓을 따로 연다.

8
