comfy-monitor

A mod (plugin) that shows ComfyUI's queue, VRAM, RAM and GPU usage in a status line and a graph panel inside Claude Code, for when you run ComfyUI without its window.

v0.3.0 12 tests passing plugin validate passing Stage 1 (MVP) done 2026-10-12

WHYWhy I made it

When Claude Code runs ComfyUI headless to make videos, there's no screen showing how busy the GPU is or how many jobs are left in the queue. Looking around, there are tools for watching inside the ComfyUI window (Crystools, Elegant Resource Monitor), but no plugin that graphs ComfyUI usage inside Claude Code. So I built one.

In short

If you work with the ComfyUI window open, Crystools is enough. This mod is for when you run it without a window (headless).

FEATURESFeatures

One-line status summary

Keeps running and queued counts, VRAM and GPU usage always visible. If ComfyUI stops responding, it switches to "off."

10-minute graph panel

Shows GPU, VRAM, RAM and queue as graphs of the last 10 minutes (300 samples).

Safe shutdown

stop only shuts down the ComfyUI that Claude started, and asks first if jobs are still left.

INSTALLInstall

Commands go in two places

Type claude plugin … commands in PowerShell, and slash commands like /reload-plugins and /comfy-monitor … in the Claude Code prompt.

Permanent install (recommended)

  1. Check the plugin folder. The hidden .claude-plugin folder must be there too. 
    claude plugin validate <plugin folder>
  2. Register the folder as a local marketplace and install. 
    claude plugin marketplace add <plugin folder>
claude plugin install comfy-monitor@hg-local --scope user
claude plugin list
  3. If it shows as enabled in plugin list, the install is done. In a Claude Code session that's already open, run /reload-plugins. A notice during install saying "5 userConfig options are not set" is normal. The defaults are used.

Test once without installing

claude --plugin-dir <plugin folder>

Moving to another PC

Copy the whole folder and install in the order above. The default for comfyBin is a path on the PC it was made on, so change it to your own comfy-cli path on the new PC. This value is only used by /comfy-monitor stop.

USAGECommands

CommandWhat it does
/comfy-monitorOpens the graph panel. Turns the monitor back on if it was off.
/comfy-monitor onTurns the monitor on and opens the panel.
/comfy-monitor offTurns only the monitor off. Stops polling and clears the status line.
/comfy-monitor stopShuts down ComfyUI itself (comfy stop). Asks first if jobs are left.
/comfy-monitor stop nowShuts down right away even if jobs are left.
/reload-pluginsReloads the mod files after editing them, without restarting.
off and stop are different

off only turns off the monitor, and ComfyUI keeps running. stop shuts down ComfyUI, so any generation in progress stops too. stop only shuts down a ComfyUI that Claude (comfy-cli) started in the background, not the ComfyUI Desktop app. The mod has no command to start ComfyUI, so ask Claude to "start ComfyUI" or run comfy launch --background.

CONFIGSettings

Change these in Claude Code's /config or under pluginConfigs.comfy-monitor in the settings file.

intervalSeconds2Polling interval (seconds)

autoStarttrueWhen off, doesn't poll at session start and waits for on

HOWHow it works

Session start→2 s timer→/system_stats · /queue · nvidia-smi→Ring buffer of 300 (10 min)→Status line · panel
ItemWhere it's read from
VRAM, RAM, versionGET /system_stats
Running and queued countsGET /queue
GPU usage, temperature, powernvidia-smi --query-gpu=utilization.gpu,temperature.gpu,power.draw
Recent job times (Stage 2)GET /history?max_items=5
Step progress (Stage 2)progress and executing on the /ws websocket

After 3 missed responses in a row, ComfyUI is shown as "off," and from then on it checks every 10 seconds. /comfy-monitor on works fine even when ComfyUI is off. /system_stats doesn't include GPU usage, so nvidia-smi is used alongside it.

NOTESWhat I learned building it

  • ValidationHelper functions that take $ must be top-level function declarations in the file to pass validate.
  • TerminalThe terminal view also receives the SVG key but draws nothing, so it switches to sparklines depending on the type of screen.
  • TimerReloading the module rejects any poll in progress, so the Promise in the timer callback must always be caught.
  • WebsocketWebsockets can't be used inside a mod, so Stage 1 polls every 2 seconds, and real-time progress comes in Stage 2 through a helper script.
