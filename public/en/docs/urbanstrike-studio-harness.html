UrbanStrike Studio Harness

This is a design for running a game studio with 14 team leads as Claude agents, splitting the work from planning through launch and maintenance into 7 stages separated by gates. As CEO, HG decides only the vision, key gate approvals, and budget and licensing; the agents design and carry out everything else: planning, design, production, QA, launch, and operations. The PD agent is the executive producer (the orchestrator), and the other 13 are discipline leads. The first project is UrbanStrike, which is now late in S1 pre-production, right before the G1 vertical slice.

UE 5.8.3 · Blueprint firstBlender 5.2 · Houdini 19.5 FXLocal only (no GitHub)Claude Code subagents + skills + hooks
CEO = HGVision, gate approvals, budget and licensing, public releases only. Agents design and execute the rest
14 leads1 PD + 13 discipline leads. Each has one definition file, with owned folders and deliverables
7 stages · 6 gatesConcept → Pre-production → Production → Content complete → QA → Launch → Live ops
4-step reviewSelf check → cross review → QA verification → PD decision; gates need HG approval
120fpsAn 8.33ms-per-frame budget at 1440p Epic on an RTX 5080, measured every sprint from S1
3 kinds of reportsA plan report before work, a done report after, and a delay report when something runs over 10 minutes
Files are the contractTickets, handoffs, and gate reports travel as md files in the Studio folder

04Optimization · 120fps on an RTX 5080

We don't save optimization for the end; we measure every sprint starting in S1. The TD (Technical Director, tech lead) owns it, QA automates the measurements, and TA and A3 handle GPU content cost.

Reference hardwareNVIDIA RTX 5080, Windows 11, DX12/SM6
Resolution & quality2560×1440, engine scalability Epic, TSR quality mode, Lumen, VSM, and Nanite on
Target frame rateAverage 120fps (8.33ms per frame), 1% low at 90fps or higher, zero hitches (frames over 50ms)
Secondary targetAverage 90fps or higher at 4K with TSR 50% (for reference)
MemoryVRAM at 12GB or less (75% of the 5080's 16GB), system RAM at 12GB or less

Frame budget (8.33ms)

ItemBudgetMain driversOwner
Game thread6.0msBP Tick, AI (StateTree), animationTD AN
Render thread6.0msDraw calls, visibility, shadow setupTD TA
GPU total8.0msSum of the items below (0.3ms headroom)TD
Lumen GI & reflections2.5msLumen quality, reflection methodTA
Shadows (VSM)1.2msNumber of shadow-casting lightsTA LD
Base pass·Nanite2.0msTriangles, material costA3 TA
FX & translucency0.5msParticle count, overdrawTA
Post-processing & TSR1.3msTSR, bloom, exposureAD TA
UI0.5msHUD drawingUI

Optimization by stage

StageTo doGate criteria
S1 Pre-productionLock the budget table, fix the performance test map and camera path, measure the baselineG1: average 120fps on the test path
S2 Productionperf_capture runs automatically every sprint; a performance ticket when over budgetRegressions over 5% get fixed within that sprint
S3 Content completePer-asset budget checks (triangles, textures, materials), GPU measured per areaG3: every area within budget
S4 Polish & QAOptimization pass: fix the top 5 bottlenecks, shader precompilation (PSO), remove hitchesG4: target met in the packaged build
S6 Live opsPerformance regression test on every patchWithin 5% before and after each patch

Measure → fix loop

1

Measure. A fixed 60-second path, stat unit and stat gpu, saved to CSV with csvprofile (perf_capture.py, -csvprofile)

2

Find the bottleneck. Start with whichever of Game/Render/GPU is longest (stat unit, Unreal Insights traces)

3

Dig in. ProfileGPU and stat gpu for the GPU, Insights timing for the CPU (ProfileGPU, Insights, NVIDIA Nsight (optional))

4

Fix. Fix only the single biggest item, then measure again (a ticket for the owning lead)

5

Record. Log the before/after numbers in Studio/perf/YYMMDD.md (Studio/perf)

Tools: stat unit / stat gpu / stat scenerendering / stat rhi · Unreal Insights · ProfileGPU · csvprofile · startfpschart · memreport -full · r.ScreenPercentage · sg.* scalability · Lumen and Nanite visualization views · NVIDIA FrameView (optional)

06Harness structure

When Claude Code runs in the project folder, it calls the leads in .claude/agents as subagents. Leads never talk to each other directly; they exchange only files (tickets, handoffs, gate reports) in the Studio folder. That way the state survives even if a session drops, and HG can check it anytime through the Obsidian copy.

HooksWhat they do
SessionStartInjects the state.yaml summary, open tickets, and this week's gates into the session.
PreToolUse · BashBlocks git push, git remote add, and bulk deletes in the Content folder.
PostToolUse · Write/EditOn changes under Content or Source paths, runs asset-check (naming, size) and adds a line to the ticket log.
SubagentStopBlocks ending if the assigned ticket has no handoff file, and asks for one.
PostToolUse · Bash (running UE)If UnrealEditor exits abnormally, bumps the crash counter; on the second identical command, blocks the rerun and asks for crash-triage.
PD heartbeat (every 5 minutes)Checks the start time of in-progress modules and sends the CEO a delay report when one runs 10+ minutes over.
StopUpdates ticket status in state.yaml and sends a notification if anything needs HG's approval.

10Debugging and crash handling

When a crash repeats, narrow down the cause before running it again. The TD (Technical Director, tech lead) owns this, and QA (Quality Assurance) handles log collection and regression tests.

1

Stop. If the same crash or error happens twice, don't retry as is. Stop the current module and release the lock (editor.lock).

2

Collect. Gather Saved/Crashes/<id>/ (CrashContext.runtime-xml, UEMinidump.dmp), Saved/Logs/*.log, the command line used, and the last good commit.

3

Classify. Split by exception type: EXCEPTION_ACCESS_VIOLATION (near 0x0 means null; a random address means use-after-free or overwrite), Assertion/check and ensure, Out of memory, GPU (D3D device removed, TDR), headless-only (-nullrhi, Niagara and material compiles without rendering).

4

Check memory. Record the memory trend across repeated runs: stat memory, memreport -full, -llm. If suspicious, reproduce with -stompmalloc (detects use-after-free), -d3ddebug, -onethread.

5

Minimal repro. Split the module further and binary-search down to the offending node, asset, or script line. Confirmed once it reproduces 3 times under the same conditions.

6

Record. Studio/bugs/crash/C-####.md: symptom, count, log paths, top 5 call stack lines, hypothesis, attempts, workaround, risk, root-fix plan.

7

Separate workaround from root fix. A workaround (e.g., running in the editor GUI instead of headless, turning a feature off) is marked as a workaround, and a separate root-fix ticket is opened.

8

Report. On the second crash, send the CEO a crash report (cause hypothesis, next attempt, new estimate). If 3 different attempts fail, escalate to the TD + CEO decision (cut scope or switch approach).

9

Regression test. Every fixed crash is added to qa_integration.py as a repro test, so each run checks that it doesn't come back.

  • 2026-10-26: FX v2 Niagara headless crash 7 times → fixed with a workaround (commit 7eece96). The same run was repeated until it reached 7 crashes; under these rules it should have stopped at the second and started by classifying the logs.
